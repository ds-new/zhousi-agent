# 评估与进化的生产合同

## 发布证据

发布必须使用配置好的真实 Agent executor 执行 5–100 道当前任务。每道任务必须具有非空 `expectedContains` 断言。执行器只收到输入、任务 ID 和固定版本快照，不收到评分答案。普通 `/traces` 上传仅用于可观测性，不能作为发布证据。

每个执行批次在调用第一道任务前持久化开始标记。发布只接受最新单一批次：每个当前任务恰好一条执行结果，任务集与快照 SHA-256 指纹一致，输出及耗时/Token 等数值有效，证据不超过 24 小时。首题失败、部分失败、新增任务、重复任务结果、版本不符均阻断发布。存储层在实际 pin 操作内再次验证指纹及批次，防止校验与写入间的竞态。调用方传入的旧 gate 不被信任。

默认门禁为通过率 >= 85%、P95 延迟 <= 8 秒、工具成功率 >= 90%。任务级通过要求命中至少 80% 指定词项并满足任务自己的时延预算。该评分是可重复的确定性验收，不能证明任意业务语义正确；安全敏感任务应使用业务方定义的严格断言和人工复核。

## 独立保留集

黄金任务创建接口接受 `split: "train" | "holdout"`，省略时为 `train`。自动进化要求至少 5 道训练任务、5 道独立保留任务，总计不超过 100；两组不能具有相同的归一化输入。

优化器仅收到训练任务和训练执行结果。先只根据训练成绩选择候选，再执行一次基线与候选的独立保留集比较。候选必须通过保留集门禁，并严格优于保留集基线；训练提升但保留集不提升会标记失败，不生成候选。进化期间任务集变化同样失败。报告中的 `evalScoreDelta`、基线和最终通过率来自保留集；各轮 `gepaRounds` 是训练成绩，两者用途不同。

任务不足时禁止自动验证或自动发布。完全未配置任务的手动提案只能进入审核，不能把优化服务自己声称的提升当成实测结果。L2 变更仍需审批；未完成候选的运行不能提前批准。评估流量使用临时运行环境，不能读写正式会话 Memory。

## 并发、重放和恢复

存储层拒绝同一 Profile 的并发活动进化；执行和定时周期使用分布式租约。最终候选不可重写，终态不可被重放回调复活，也不能把其他既有版本冒充当前候选。基线已被其他发布替换的候选不能覆盖新的生产版本。执行或优化服务异常使未完成运行进入失败。

进程崩溃后数据库租约自动释放，但活动运行状态被保留用于排查。运维可通过已有 reject 接口拒绝 `running` 或 `awaiting_review` 运行后重试；已拒绝运行的迟到回调不能发布。该机制不承诺对外部工具副作用执行撤销。

## 团队评估

团队评估固定 Root 版本和全部 Worker 版本，跨 Workspace Worker 被拒绝；输出来自真实 Worker executor。评估记录保存逐任务成绩和 Worker 版本清单，支持历史复核。协作分数依据交接次数/延迟、工具成功率；它是运行诊断指标，不能单独证明团队比单体更优。团队评估不能替代 Profile 的完整发布批次。

## 外部验收条件

上线前仍须由业务方提供代表性的训练/保留任务、真实模型和真实 MCP 测试环境，验证误报率、成本与 SLO。保留集不应无限重复使用，应定期轮换并引入未参与任何优化的最终测试集；5 道保留题只是配置下限，不能给出统计显著性。生产主机需同步时钟。真实业务收益、长期退化监测、A/B 或灰度实验与工具副作用回滚不由当前确定性测试代替。
