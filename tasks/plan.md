# 企业智能体能力核查与补齐

以 docs/specs/tob-agent-platform.md 为已有验收规格。现有 96 项 TypeScript 测试在允许本地端口的环境全部通过，但并不能证明真实 Agent/MCP 执行或数据库重启恢复。

## 顺序与验收

1. 隔离：补齐 HTTP 资源归属、管理权限、数据面内部接口认证与错误处理；跨租户请求必须在任何写入前拒绝。
2. 记忆：用失败测试复现治理丢内容、阈值无效和异步覆盖；保留可恢复原文、遵守容量和 TTL，提供租户命名空间。
3. MCP：修复池 key/限额/敏感范围，添加真实协议连接与并发初始化、关闭和超时；用本地协议服务验证热复用。
4. Agent 与协作：引入真实执行器，执行输入不含评估答案；流水线传递完整上下文、worker 受 Workspace 边界约束；未配置执行器必须明确失败。
5. 评估/进化：任务与 trace 显式关联、拒绝伪造默认成功，评估候选的真实结果，防止退化候选自动发布。
6. 持久化与交付：核查 Postgres 恢复、Skill/model/KB 运行链路、轻量启动指标；跑完整测试与 Python 测试，输出逐项证据和剩余限制。

每项先复现缺陷，再修复并执行相关测试。外部供应商、真实数据库或 DSH 若不可用，记录为未验证，不能用替身测试宣称生产验收。
